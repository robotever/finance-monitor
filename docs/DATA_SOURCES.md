# 数据源策略

## 原则

1. 每个指标必须有明确的首选来源、单位、时间和身份口径。
2. 来源失败不等于数值为零，也不自动授权切换另一来源。
3. Wind 与妙想的行业／概念定义不同，不能仅凭同名字段直接拼接。
4. 浏览器只读取派生结果；凭据和原始响应留在本地。
5. 数据源切换必须显式、可追踪、可回滚，并通过同口径对比后启用。

## 指标覆盖

### Wind 板块数据

当前截面批量接口已验证：

- 涨跌幅、5 日涨跌幅、20 日涨跌幅；
- 成交额、换手率；
- 当日、近 5 日、近 20 日主力净流入；
- 上涨、下跌、平盘家数。

单板块串行历史接口已验证日 K 线，并可据此计算 20／60／250 日价格位置。当前截面为 3 个批量请求；完整历史回填仍需要对 110 个板块分别调用，不能按批量截面的成本估算。

限制：K 线接口不提供带日期的历史资金和历史涨跌家数。当前滚动字段不能伪装成历史序列。

### 妙想板块数据

2026-11-15 的代表性查询已返回：

- 成份区间涨跌幅；
- 成交额、换手率、主力净流入；
- 上涨、下跌、平盘家数；
- 多个连续交易日的部分字段。

这证明妙想能够补充大部分评分原料，但尚未证明：

- 35 个 Wind 行业和 75 个 Wind 概念都有稳定的一对一对应；
- 一个或少量请求能批量返回完整板块宇宙；
- 交易时间内更新时间稳定满足 15 分钟刷新；
- 字段名、表结构和单位长期稳定；
- 历史深度足够覆盖所有 60／250 日位置计算。

## 已批准的目标刷新结构

用户需要盘中操作参考，因此目标是 15 分钟刷新。为控制 Wind 成本，按数据变化速度分频：

| 数据组 | 目标频率 | 首选来源 | 说明 |
|---|---:|---|---|
| 35 行业＋75 概念盘中行情／资金／广度 | 每 15 分钟 | Wind | 保持板块评分同口径 |
| 全市场宽度和六类风格 | 每日 4 个关键时点 | Wind | 相对慢变量 |
| A 股长期日线与复权基线 | 收盘后按日增量 | 同花顺离线库 | 供历史位置、标签和评价，不替代盘中字段 |
| 全球日频／月频序列 | 按来源频率 | FRED／妙想 | 不伪装成盘中实时 |
| 新闻与事件 | 5 分钟或按需 | 新闻源／妙想搜索 | 不直接进入量化评分 |
| 板块备用数据 | 失败时显式启用 | 妙想 | 映射和盘中验证通过后才可启用 |

该结构是已确认的设计方向，尚未部署。按 2026-11-15 的单次实测平均值估算，Wind 约 59 个请求、35–36 积分／交易日；供应商实际可能按接口或数据量计费，必须以完整交易日实测校准。

## 数据源切换设计

后续实现应满足以下要求：

### 1. 固定来源注册

每个数据组配置：

- `primary`：正常来源；
- `fallback`：允许的备用来源；
- `sourceMode`：实际使用来源；
- `mappingVersion`：跨供应商身份映射版本；
- `observedAt`：来源观测时间；
- `fallbackReason`：切换原因。

### 2. 版本化身份映射

Wind `*.WI` 与东方财富 `BK*` 之间建立人工审核的版本化映射。映射至少包含来源代码、规范名称、板块类别、匹配状态、生效日期和备注。名称模糊匹配只能产生候选，不能直接进入生产。

### 3. 不按字段静默拼接

同一板块同一评分时点原则上使用一个来源的完整字段组。如果备用来源缺少某项，降低完整度并披露缺失；不从另一个来源补一个字段后继续声称是同口径分数。

### 4. 切换门禁

妙想成为板块备用源前至少验证：

- 全量身份映射通过；
- 盘中连续多个时点的数据时间满足要求；
- 单位和正负方向一致；
- 同一板块关键字段与 Wind 差异在可解释范围内；
- 调用次数、延迟和额度可接受；
- 来源切换在前端和 payload 中可见；
- Wind 恢复后有明确回切规则。

## 新鲜度和缺失处理

- 日频、月频和盘中指标分别使用不同新鲜度阈值。
- 供应商缺失标记如 `.`、空字符串或 null 保持缺失。
- 当前字段不能填充历史日期；滚动 5/20 日字段不能复制成逐日历史。
- 新板块历史不足时，位置和机会完整度自然降低。
- 失败后保留最后成功值仅用于展示，并标记 `stale`；不得进入声称“当前”的评分。

## 新闻来源

新闻源清单由 `src/api/news-policy.mjs` 控制，当前每个来源最多展示 10 条。新闻用于事件背景和研究线索，不直接进入市场或板块评分，以避免来源数量和文本热度扭曲量化结果。

## 凭据与数据保留

- `MX_APIKEY`、Wind 授权、同花顺 API Key 和 Cloudflare 发布令牌只能通过环境变量、供应商凭据存储或 Cloudflare Secret 提供。
- 同花顺 API Key 已保存到官方 CLI 的用户凭据存储，不写入仓库、命令记录、数据库或前端。
- 原始供应商响应只可用于临时诊断，不提交仓库、不发布到前端。
- 同花顺离线库位于 Financial Knowledge Repository 的共享 `data/` 目录，不提交 Git；对外页面只发布必要的派生评分和来源元数据，并在使用前确认供应商授权与再分发边界。
- 长期保存的是版本化派生指标、评分、来源元数据和必要审计证据。
- 临时能力测试输出应写入受控临时目录并可安全删除。
