# 市场看板运行保障修复设计

## 意图

2026-11-16 的首个真实交易日表明，采集链路本身可以工作，但运行机器在午后处于电池供电和睡眠状态：14:00 窗口没有执行，收盘任务在窗口末端才恢复并以 `WINDOW_EXPIRED` 安全失败；13:06 的普通行情批次只留下笼统的 `INVALID_PAYLOAD`，无法从安全日志判断具体校验规则。

本修复保证接通电源的 Mac 在 A 股交易时段不会因空闲进入系统睡眠，同时保留现有上海时间窗口、15:30 可得性边界、评分算法、供应商和发布契约。低电量电池模式下不强制保持唤醒。

## 目标

- 上午第一次服务唤醒后，在工作日 09:25–15:35（Asia/Shanghai）建立单一的 AC-only 防系统睡眠守护。
- 守护进程跨越每个五分钟采集子进程，并以文件锁防止重复实例。
- 仍然只允许 15:00–15:30 启动和完成正式收盘采集；不把迟到数据伪装成准时数据。
- `INVALID_PAYLOAD` 在私有健康状态中增加有限、枚举化的 `validationRule`，不记录供应商原文、字段值、凭证或完整 payload。
- 现有 v2/v3 数据、频率、评分和 Cloudflare 接口不变。

## 非目标

- 不在电池供电时强制整日保持唤醒。
- 不绕过合盖睡眠、断电、退出登录或网络中断。
- 不修改 15:30 的 PIT／回测边界。
- 不把校验失败的数据发布到看板。

## 方案比较

1. **放宽收盘截止时间。** 能接受 15:38 的结果，但破坏“15:30 前可得”的研究口径，拒绝。
2. **让每次采集自身防休眠。** 只能保护正在运行的几分钟，无法阻止两次任务之间进入睡眠，不足。
3. **AC-only 交易时段守护（采用）。** 上午服务正常运行后保持到 15:35；文件锁保证单实例，使用 macOS `caffeinate -s` 只在接通电源时阻止系统睡眠。兼顾可靠性和电池安全。

## 设计

- 新增 `ops/macos/market_dashboard_awake.py`：计算上海工作日剩余会话秒数；以私有状态目录中的非软链接锁文件取得独占锁；运行 `/usr/bin/caffeinate -s -t <seconds>` 并持锁到会话结束。
- wrapper 在执行看板 CLI 前，以脱离当前进程组的方式启动守护入口。入口在窗口外或已有实例时立即退出；失败不得阻止数据任务，且只输出固定安全错误。
- `ValidationError` 携带枚举化规则名；`_require` 默认规则保持 `contract`，对“对象无任何可用分数”等关键边界使用具体规则。健康文件只写 `validationRule`，成功时清除。
- 单元测试固定上海时间验证窗口、跨时区、周末、单实例和软链接拒绝；wrapper 测试验证守护入口不会改变原有参数；作业测试验证规则名只进入私有健康状态。

## 验收

- 新测试先在旧实现上失败，再在修复后通过。
- Python 全量测试、Node 全量测试和生产构建全部通过。
- 不手工调用 Wind，不制造补写的收盘快照。
- 稳定 checkout 更新后重新加载现有 LaunchAgent，使 wrapper 变更生效；下一交易日仍需接通电源完成真实验收。
