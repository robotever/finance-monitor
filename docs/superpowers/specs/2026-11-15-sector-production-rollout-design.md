# 板块轮动生产试运行设计

## 意图

把已经通过合成数据验收的行业/概念轮动模块推进到可观察的真实数据试运行，同时保留旧首页、严格披露证据不足，并避免影子任务重复消耗 Wind 积分。用户已明确授权连续完成，不再逐项确认；上线仍必须可回滚、不可把试运行写成评分有效性已验证。

## 目标

- 旧首页继续保持交易时段每 15 分钟更新。
- 09:45、11:30、14:00、收盘四个轮动时点与旧首页共享同一批 Wind 数据；重叠时点不得重复取数。
- 交易日资格由当日 Wind 市场观测日期证明并本地缓存；不依赖人工维护未来节假日表，不增加单独日历调用。
- v3 数据可通过现有鉴权发布端点写入 D1；失败不推进本地成功 bucket，可安全重试。
- 生产 UI 显示真实 v3 数据，但固定标记为“观察期/证据不足”，`releaseEligible=false` 仍表示评分有效性没有通过评价，不被 UI 开关伪造成已验证信号。
- 部署迁移、Functions、前端与稳定服务配置后，完成无 Wind 的只读验收；首个真实交易时点再做数据验收。

## 非目标

- 不调整强度、机会、风险公式或阈值。
- 不用合成数据填充生产 D1。
- 不声称十日评价、预测能力或交易信号已经通过。
- 不删除 v2 快照、旧表、影子状态或回滚部署。

## 约束

- 供应商调用保持串行；同一进程、同一周期最多执行一次完整 `collect_batches`。
- 轮动时点先执行，随后旧首页复用缓存结果，避免旧首页耗时导致轮动窗口过期。
- 非交易日最多允许一次现有批次探测；当日观测日期不匹配后写入私有负向日历缓存，当天后续唤醒不再取数。
- 只有来源时间属于当前上海日期、收盘来源时间不早于 15:00 的记录才可作为正式收盘。
- 生产 v3 发布仍使用 `MARKET_DASHBOARD_PUBLISH_URL` 和 Bearer token；凭证不得进入参数、日志、仓库或测试。
- 所有新行为先有失败测试；Python、Node 全套和生产构建必须通过。

## 方案比较

### 方案 A：保留两个进程，各自采集

改动最少，但每日额外四次完整 Wind 采集，按已测 68 积分约增加 272 积分；拒绝。

### 方案 B：单进程组合周期，共享惰性缓存（采用）

轮动与旧首页仍复用现有独立状态/锁/校验边界，只在编排层共享一次采集结果。风险和改动范围可控，失败可定位，能够在不重写评分主流程的前提下消除重复计费。

### 方案 C：重写成单一 v3 作业并停掉 v2

长期最简，但一次切换采集、持久化、发布和兼容层，回滚风险过大；本轮不采用。

## 运行流程

1. LaunchAgent 每 300 秒唤醒 wrapper。
2. wrapper 在轮动开关启用时调用一个组合周期，不再派生两个 Python 进程。
3. 组合周期先判断私有负向日历缓存；已确认非交易日直接返回。
4. 轮动窗口命中时先执行轮动任务；惰性 collector 首次调用 Wind 并缓存批次。
5. 批次的 Wind 市场日期必须等于上海当前日期，否则记录当日非交易并终止，不发布陈旧数据。
6. 同一周期再执行 v2；若该 15 分钟 bucket 需要采集，复用同一批次。
7. `MARKET_DASHBOARD_ROTATION_PUBLISH=1` 时，v3 先通过现有校验和鉴权端点发布，成功后才推进轮动本地状态；关闭时继续只写影子状态。
8. D1 保持 v2/v3 并存；生产 UI 优先加载 v3 观察数据，v2 仍为独立回退。

## UI 解释边界

- 生产 v3 区域固定显示“真实数据观察期”。
- `releaseEligible=false`、`safeCodes` 和冷启动状态继续保留，不能因上线而改成通过。
- v3 暂无快照或校验失败时回退 v2，不显示合成分数。
- 合成验收模式继续隔离，生产构建不得包含“测试数据”适配器行为。

## 部署与回滚

- 先应用远端 `0002_sector_rotation.sql`，再构建带生产观察开关的普通生产包并部署 Pages。
- 部署后只读验证：首页、v2 API、v3 空状态、未授权发布拒绝、D1 迁移状态。
- 最后在稳定 checkout 更新 wrapper/配置开关；不 kickstart、不手工调用 Wind，等待下一自然交易时点。
- 回滚顺序：关闭 `MARKET_DASHBOARD_ROTATION_PUBLISH`，关闭轮动观察开关或部署此前生产版本；保留 D1 表和历史。

## 验收

- 重叠时点的测试 collector 调用次数严格为 1。
- 非交易日期证据写入后同日后续周期 collector 调用次数为 0。
- v3 发布失败不写成功状态，重试成功后只产生一份幂等 D1 观察。
- 普通生产 UI 可显示真实 v3 且明确观察期；无 v3 时仍显示 v2。
- 生产部署不注入 fixture，不调用 Wind；首个真实交易时点后记录 35/35 行业、75/75 概念、完整度、耗时、积分和发布状态。
