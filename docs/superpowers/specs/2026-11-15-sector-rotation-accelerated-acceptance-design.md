# 板块轮动加速验收与分级发布设计

**日期：** 2026-11-15
**状态：** 待确认

## 意图

先让用户看到并验收产品，再用最小必要的真实交易日证据控制发布风险。十个交易日继续用于上线后的评分观察，不再阻塞用户验收和测试版发布。

## 已选方案

采用“临时验收页面 → 一个完整交易日验证 → 可回滚测试版发布 → 十交易日上线后观察”。

未采用的方案：

- 等待 2–3 个交易日再验收：风险更低，但仍延迟用户反馈。
- 立即在正式网址开放：速度最快，但当前没有真实 v3 正式收盘数据，容易把数据缺失误认为产品缺陷。

## 阶段与门槛

### 1. 临时验收页面

- 提供可点击、支持电脑和手机的临时页面。
- 使用明确标注的测试数据，仅用于验收布局、信息结构、术语和交互。
- 不迁移 Cloudflare D1，不发布 v3 数据，不改变现有正式页面和 v2 服务。
- 用户反馈形成问题清单，确认后再修改产品。

### 2. 一个完整交易日验证

- 至少成功取得一个有效交易日的正式收盘影子快照。
- 行业身份必须为 35/35；概念身份至少达到 72/75。
- 不得出现身份、单位、未来时间或误发布错误。
- 影子任务必须继续跳过发布，v2 更新不得受影响。
- 完整度和机会分可以标记“观察中”，不要求一个交易日证明预测有效性。

### 3. 测试版发布

- 用户完成界面验收且单日运行门槛通过后，才申请测试版发布授权。
- 页面明确显示“测试版／观察中”，数据不足时不输出伪精确结论。
- 发布动作仍需单独授权，包括数据库迁移、v3 数据发布和界面功能开关。
- 保留一键回退到 v2 的边界；出现严重数据或接口问题立即回退。

### 4. 上线后十交易日观察

- 原十交易日规则改为持续质量评估，不再作为测试版发布的前置条件。
- 继续记录成功收盘数、覆盖率、完整度、延迟、榜单变化及安全错误。
- 十日结束后评估评分稳定性和初步历史有效性；不把十日结果表述为成熟回测或收益承诺。
- 未通过时允许调整评分版本或回退，不影响 v2 数据和新闻模块。

## 非目标

- 临时验收页面不代表真实市场信号。
- 一个交易日不能证明机会分具备预测能力。
- 本设计不授权推送 GitHub、Cloudflare 部署、D1 迁移或正式功能启用。

## 验收成功标准

- 用户能够在电脑和手机上完整操作行业/概念、机会/主线/风险、历史矩阵和详情。
- 测试数据标签清楚，不与真实数据混淆。
- 用户反馈可以逐项记录、修改和复验。
- 测试版发布前至少有一个真实完整交易日的安全影子记录。
