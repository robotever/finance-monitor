# 同花顺历史行情适配层设计

## 意图

为 NewsMonitor 建立一个独立、只读、可验证的同花顺 Financial API 本地历史行情入口，作为历史位置、远期收益标签和评分评价的基础设施。该入口不得改变现有 Wind／妙想盘中职责，也不得在板块身份映射未经验证时把股票级历史冒充成板块历史。

## 目标

- 通过同花顺官方 CLI 只读查询共享 DuckDB，不在项目中引入新的数据库运行时。
- 支持不复权、前复权和后复权日收盘价，结果按日期和证券代码稳定排序。
- 对证券代码、日期范围、分页结果、重复行、价格和供应商响应结构进行严格校验。
- 提供仅包含覆盖率和质量信息的审计输出，不输出 API Key、原始响应或不必要的价格明细。
- 为后续历史百分位、远期标签和评价程序提供版本化接口，但本阶段不接入生产评分。

## 非目标

- 不改变 `sector-score-v0.2`、Cloudflare 数据、页面或生产调度。
- 不用当前成份股回算历史板块表现，不制造带幸存者偏差的行业／概念历史。
- 不把同花顺 320 个行业目录自动映射为现有 35 个 Wind 行业或 75 个 Wind 概念。
- 不下载或再分发供应商原始数据，不在 Git 中保存 DuckDB。
- 不替代 Wind／妙想的盘中资金、广度、换手或新闻数据。

## 约束

- 使用 Python 标准库和已安装的同花顺官方 CLI，不新增 `duckdb` Python 依赖。
- SQL 只能由经过白名单校验的证券代码、ISO 日期、固定视图和整数分页参数组成；不接受任意 SQL。
- 查询只允许 `v_daily`、`v_daily_qfq`、`v_daily_hfq`。
- 官方 CLI 返回非零、`ok != true`、截断、结构异常、越界日期、未知证券、重复日期或非正有限收盘价时失败关闭。
- API Key 继续由官方 CLI 用户凭据存储管理，模块和测试不读取凭据。

## 方案

### 方案一：Python 直接连接 DuckDB

查询最灵活，但需要新增二进制依赖，还会绕开官方工具的只读边界和数据库版本管理。当前项目没有该依赖，因此不采用。

### 方案二：每次调用远端历史接口

无需本地适配，但重复消耗额度、速度较慢，且不能利用已经验证的 10 年本地库。不采用。

### 方案三：复用官方 CLI 的只读 `db query`（采用）

项目只构造固定格式的分页查询并校验精简结果。供应商工具负责打开数据库和兼容其 schema；项目保持无额外运行依赖。代价是需要显式处理分页和 CLI 响应边界。

## 接口与数据流

新增 `tools.market_dashboard.hithink_history`：

1. `load_daily_closes(...)` 接收显式 CLI 路径、数据库路径、证券代码、起止日期和复权方式。
2. 模块构造固定视图的只读分页 SQL，通过可注入 runner 调用官方 CLI。
3. 每页响应转换为精简行：`id`、`date`、`close`、`adjustment`、`source`。
4. 返回 `hithink-daily-history-v1` 批次，披露请求证券、返回证券、缺失证券、页数和完整状态。
5. `audit_history(...)` 只生成行数、证券数、首末日期、缺失证券和完整状态，供人工和自动门禁检查。

命令行入口要求显式提供 CLI 和数据库路径。成功时输出 `hithink-history-audit-v1` JSON；无数据、缺失证券或无效输入时退出非零并返回安全错误码，不显示原始工具错误。

## 与评分评价的边界

同花顺股票日线可以立即用于股票级研究、交易日核对和未来个股收益标签，但现有评价器的身份是 Wind 行业／概念指数。两者只有在以下任一证据成立后才能连接：

- 获得与现有板块代码同口径的指数历史；或
- 获得逐日有效的成份历史并建立版本化聚合规则。

当前成份快照不足以回算历史，因此第一阶段只交付适配层和审计，不修改 `rotation_evaluation.py`。

## 验收

- 单元测试证明分页、复权视图选择、稳定排序、缺失证券披露和所有失败关闭条件。
- 使用真实本地库查询两只证券的小日期窗口，结果与官方 CLI 原始小样本行数、日期和收盘价一致。
- 项目 Python 全量测试、Node 测试和构建保持通过。
- 文档明确路径、命令、安全边界和尚未完成的板块映射。
