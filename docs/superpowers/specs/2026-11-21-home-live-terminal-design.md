# 首页研究终端与实时快讯设计

状态：2026-11-21 用户整体批准，自主开发、验证并上线。

## 目标与用户选择

首页用于快速观察全市场联动及最新事件，并进入既有板块研究。用户已选择深蓝研究终端；全球联动固定行情；中国市场与全球重要宏观，实时快讯只保留最近2小时。希望一次确认后自主开发、验证、部署，避免反复催促。

## 交付范围

1. 深海军蓝背景、统一青蓝重点色，红绿仅用于涨跌/风险必要语义。文字可读性、首屏重点、紧凑信息密度优先于炫光动画。保留首页市场研究雷达、债务风险及新闻阅读能力，保留清晰的板块研究入口，避免改变既有板块计算及运行链路。
2. 首页上部行情区固定8项：上证指数、创业板指、恒生科技、纳斯达克指数、黄金、原油、美元指数、美元/离岸人民币。提供价格、涨跌幅、可切换走势图。精确代码、现货或期货口径由实施时核验，界面明确名称及口径，不静默替换为ETF或其他代理资产。
3. 顶部横向与右侧纵向共用规范化快讯流，按真实发布时间倒序排序、跨源去重，展示来源及北京时间。计划60秒刷新，服务器适当短缓存合并访问。只保留最近2小时；无有效快讯显示空态，不用旧消息或演示数据填充。失败显示状态，现存缓存到期仍须退出实时区。提供暂停滚动及减少动画支持。
4. 来源卡片继续最多10条；较慢文章可进入下方阅读区，不能冒充实时快讯。先验证现有华尔街见闻、金十、市场资讯等候选源，再决定实时入选清单；用户过去移除的财联社、雅虎、Hacker News、GitHub趋势、Product Hunt、澎湃、36氪、Reddit不自行恢复。
5. 桌面及手机适配、真实线上请求验证、故障及过期边界测试、文档与变更记录更新、现有Cloudflare地址部署。

## 当前问题与事实

- 右侧按来源顺序拼接；顶部仅取每源首条，没有共享按时间排序的快讯流。
- 新闻每5分钟刷新。接口的ctime/display_time等被转换为显示文本，绝大部分没有保留timestamp，RSS发布时间也未解析，无法可靠判断新旧。
- 页面存在大量来源专属颜色、零散内联样式。首页AppHeader、HomeView、NewsTicker、VerticalTicker及相关卡片需要统一视觉。
- Cloudflare已有新闻代理。新闻可通过云端读取，不必沿用Mac板块采集任务。
- TradingView官方组件并不保证所有资产实时或可嵌入，个人付费会员不能改变组件的数据权限；不支持注入自己的行情。官方文档：https://www.tradingview.com/widget-docs/faq/data/ 。

## 方案比较与实施建议

- 全部官方TradingView嵌入：交互成熟、工作量低，但部分品种受嵌入或延迟限制，样式与失败检测有限。
- 全部自建图表与行情服务：体验统一、时间可控，但8类资产的稳定实时来源需分别维护，范围明显扩大。
- 推荐混合：可可靠取得的行情采用统一图表，受限海外品种采用验证可用的官方嵌入；每项标明数据口径与时效。不将不可靠代理数据标成实时。该实施建议待本设计整体批准。

## 边界与自主决定

- 不新增Wind积分消耗，不购入付费数据或要求新增账号；如确有必要再征询用户。
- 不更改强度、机会、风险评分，不替换历史数据库或板块自动服务。
- 图表技术与新闻适配器由实施者按验证结果选择，遵守现有Vue、TypeScript及Cloudflare结构。增加必要依赖须说明用途并保持部署可重复。
- 60秒为检查间隔而非消息保证延迟；发布时间、获取时间和成功刷新时间分开，不能用抓取时间冒充发布时间。周末/休市保留最近市场数据并标记休市，新闻可显示暂无2小时内消息。
- 标题、链接、发布时间、来源足以支持新闻浏览；不引入LLM新闻重写或未经验证的重要性评分。

## 验收标准

- 初屏能清楚识别行情、板块入口、最新快讯；主色一致，无横向溢出。
- 固定8项目均有正确口径与真实状态；未能取得数据清楚显示不可用/延迟，不以演示值代替。
- 两个滚动区按时间统一排序、可暂停、跨源去重；在不重载页面时也自动移除超过2小时的消息。
- 单一源失败不阻塞其他来源；请求有超时及并发/缓存边界；不把失败刷新显示为新消息到达。
- 下方单源卡片最多10条，原雷达与板块入口可用。
- 测试通过、生产构建通过、真实部署与页面检查完成；明确验证结果与尚未观察到的持续稳定性。
